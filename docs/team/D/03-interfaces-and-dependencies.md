# D：接口与依赖

下列约定应与提供方确认，端点及字段不能直接按本包猜测实现为公共标准。

## 消费方

| 提供者 | 需要的最小能力                 | D 的责任                                             |
| ------ | ------------------------------ | ---------------------------------------------------- |
| A      | 服务端当前账号、学生与学院信息 | 在每个受限业务读取和写入检查资格                     |
| A      | 公共文件上传及受控访问         | 维护图片与帖子关联，明确草稿、发布和删除时的文件处理 |
| A      | 管理操作的已有身份能力         | 实现举报处理、下架及处理结果，不由客户端自报管理权限 |
| B      | 课程引用和共享资料访问         | 绑定引用，详情读取继续应用原资料权限                 |

## D 提供的业务语义

社区板块及可见范围、帖子身份和作者、评论回复关系、互动记录、未读通知及举报处理状态。地图提供校区、建筑和地点关系、办公地点说明、来源和更新时间。

业务 ID 与课程 ID、资料 ID 分开，不把名称当作永久标识。通知跳转保持对应帖子及回复定位；内容已删除或不可见时给出合适状态。

## 保存与撤销

草稿本地优先，发布和互动进入服务端；文件上传成功不等于帖子已发布。编辑、删除和修改可见范围时，文本、引用与图片访问保持一致。与 A、B 明确文件获取时执行权限的位置，不将受限内容交给永久公开地址。

地图、办事信息与个人数据分开更新，公共更新不覆盖个人草稿或课程绑定。

## 未交付依赖

公共文件未交付时可先做文本社区与图片界面的测试，不自行新建另一套文件服务。B 引用未交付时与 B 确认契约并使用测试夹具。三维资源缺失时提交所需资源形式和当前可完成的地点流程，不私自改变三维目标。
