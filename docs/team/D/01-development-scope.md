# D：开发内容与交付顺序

你负责校园社区、三维地图和实用信息，承担客户端、业务服务端、数据、接口及测试。

## 社区

提供全校和学院板块、图文帖子、编辑删除、搜索筛选及按时间或热度排序。实现评论回复、点赞收藏、个人发布参与列表和互动通知；支持举报和管理处理结果。

帖子可引用 B 的课程和资料，图片文件使用 A 的公共能力。未发布草稿本地保存，明确发布后才上传；发布失败保留草稿。服务端保存多人共享内容并检查作者、板块及被引用资料的权限。

用户显示昵称，不公开学号、手机号或报告信息。学生验证和学院资格消费 A 的结果，不通过社区自行生成资格。

## 地图与实用信息

展示来源于吉大官网的三维地图，按校区、建筑和地点组织，提供教师办公地点、科室及办事说明。支持地点、教师和科室查找，标明来源与更新时间。

服务端统一维护公共信息，客户端缓存获取结果。三维展示能力与地点数据分开验证，教师位置表示办公地点。没有三维资源时可推进地点数据与页面，但不能将二维占位标成三维已完成。

## 先后顺序

1. 先落实板块、帖子、评论、草稿及服务端权限，跑通两个账号的真实文本讨论流程。
2. 与 A 对齐图片上传、与 B 对齐课程资料引用，再补互动、通知和举报管理。
3. 地图独立跑通地点查询和详情，在实际官方资源具备后完成三维展示集成。
4. 补发布失败、学院限制、账号切换及公共更新回归。

拆分社区和地图交付，不一次铺开全部功能。后续功能仍在职责范围内，但不因本包要求在一个提交内全部实现。
