# 行为约束与协作规则

## 开始前

先阅读本包全部文件，再进入项目阅读根目录 `AGENTS.md`、`README.md`、`docs/sources/开发完整内容.md`、`docs/team-development.md` 及相关工程文档。最新账号选择见 [07-current-decisions.md](07-current-decisions.md)。本包不改变根目录维护规则，不修改 `AGENTS.md`。

检查 `git status`、当前分支和相关提交历史，保留其他人的未提交工作。先说明本次目标、复用能力和改动范围，再执行已明确的工作；只有缺失决定影响正确性时才询问。

## 代码边界

- 不扩大功能范围，不清理无关旧代码，不顺带改名、统一格式或重构相邻模块。
- 一次性逻辑不预先抽象，不创建无消费者的 Service、Manager、插件机制或空目录。
- 未知输入只在边界校验，内部使用已类型化值，不反复做防御性属性检查。
- 复用 Flutter 现有主题和公共组件，不整体改版；只有编写前端时再读取适用的前端设计技能。
- 新增 JS/TS 工具使用 `.ts`，不创建 `.mjs`。业务继续使用当前工程语言，不另建整套技术栈。
- 新依赖说明实际用途，保持既有版本及锁文件规则，不为了假设场景引入依赖。

## 公共文件与跨模块

可以在自己的 PR 中提出必要公共修改，但应列明调用方，由 A 和直接消费者共同确认。未经对齐不批量改公共模型、路由、主题、会话状态机、OpenAPI 公共 schema 或迁移入口。

每人编写自己的业务迁移；A 协调聚合和顺序。新增迁移，不改写已发布迁移；不清库重建。生成客户端通过工具更新，不手改，不整片覆盖其他人的生成结果。

业务目录之间通过确认后的公共模型或接口协作，不直接导入对方页面和私有 Store。接口表述先标记提案，合入契约后再标记可调用；不得把候选字段写成现有 API。

## 数据及验证

不提交私人学校响应、原始报告、真实邮件、账号、密码、验证码、Cookie 或令牌。测试使用合成或脱敏夹具；真实账号只在明确授权后操作。

公共依赖缺失时，可以在测试和明确的开发环境使用替身，正常应用显示真实未接入或失败状态。不得固定返回连接成功、已验证或同步成功，不在生产提供绕过身份的调试开关。

不为推测性竞态或极不可能的边缘情况增加复杂框架。遇到具体失败，再说明影响和成本；认证、资料权限、账号隔离等已有明确要求仍需落实。

## 提交与交付

使用 `codex/` 前缀的具体功能分支，一个提交和 PR 服务于同一主题；不推主分支，不自动合并。先格式化改动文件，PR 前完成相关本地测试。只在 PR 或发布分支维护 CHANGELOG，不为每个提交加日志。

创建 PR 前遵循贡献指南，由人类补充其要求的前置问题；开发和本地验证不因尚未创建 PR 而停止。创建、推送、部署等操作按当前会话实际授权执行，不因本包存在就获得生产操作权限。

交付说明记录实际修改、验证命令和结果、未覆盖事项及依赖。历史测试数、模拟结果和旧版能力不计作本轮交付。未受阻塞工作继续推进，明确列出需要谁提供什么，不以“等待 A”代替全部进展。
