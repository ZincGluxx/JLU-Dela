# E：职责及文件边界

## 主责范围

Flutter 邮箱、网课、笔记和摘要相关业务，必要 Rust 服务端、相关迁移、模型与测试。先定位新版已有实现；新增功能目录只在有实际代码时创建。

旧 `app/src/main/mail/` 和 `app/src/main/jlu/` 等实现可作为行为及字段参考，不把 Electron 的系统接口直接移入 Flutter，也不因旧版有能力就承诺新版已完成。

## 成员边界

| 成员 | 边界                                                                                       |
| ---- | ------------------------------------------------------------------------------------------ |
| A    | 提供应用身份、公共网络、来源及凭据边界、文件和备份。E 提供自己的业务实现与笔记序列化内容。 |
| B    | 提供课程引用及共享资料服务，E 不另建全局课程系统或共享资料库。                             |
| C    | 负责学习通和智慧树，E 负责学在吉大，不复制两个平台适配。                                   |
| D    | 社区和地图归 D，私人邮件与笔记不自动导入社区。                                             |

## 明确限制

不负责模型训练、模型选型、推理集群或通用聊天平台。摘要接口按自有模型实际协议接入，不引入额外模型服务作为替代产品决定。

不开发录像批量下载、公开转存、自动转写、邮箱营销群发、通用文件管理器或旧版终端和远程工程。

不默认把邮箱、全部笔记和本地资料发送给模型。摘要输入要明确，字段和日志不带凭据。来源允许观看不自动等于可以下载或分发。

播放和邮件协议需要的系统插件及依赖说明实际用途，目标平台按实际交付验证，不因 Flutter 支持某平台就承诺可运行。
