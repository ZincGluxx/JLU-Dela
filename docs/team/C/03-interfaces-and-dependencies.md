# C：接口与依赖

## 消费的公共能力

| 提供者 | 能力                                                | 接入边界                                              |
| ------ | --------------------------------------------------- | ----------------------------------------------------- |
| A      | 公共身份、本地用户作用域、来源会话与 HTTP、页面注册 | 使用现有 SourceContext 及会话机制；实际名称以基线为准 |
| B      | 课程引用及可选课表课程                              | 以标识和学期绑定，不依赖 B 的私有页面或 Store         |
| B      | 共享资料发布与引用                                  | 平台读取完成不自动发布；用户明确选择后才进入共享范围  |
| A      | 后续备份                                            | 仅个人课程映射与选定业务数据，排除来源凭据            |

## C 应对外说明

平台课程身份、绑定关系、资料目录条目、作业及截止状态的最小语义。明确哪些字段来自来源，哪些是本地备注，哪些时间是精确时刻、仅日期或相对提示。

保留来源课程与作业标识，提交入口及附件访问说明是否需要当前来源会话。不得把临时页面地址宣称为长期直链。字段和端点按现有契约演进，不自行新建重复 API。

## 数据责任

课程主身份由 B 主责；平台课程到课程的映射由 C 主责。学院资格只来自 A 的服务端身份，不能通过课程归属反向授予学院身份。

个人平台内容继续沿用已确认的本地读取路径；需要云端保存的内容限明确业务用途，不为已有 Rust 服务把所有请求改为云端代抓。

## 依赖缺失时

B 尚未合入模型时共同确认最小提案，使用隔离夹具开发绑定和展示。A 尚未接入某个真实来源时继续解析器、本地存储和页面测试；生产连接状态保持真实。真实平台账号操作需取得授权，公开夹具不包含私人资料。
