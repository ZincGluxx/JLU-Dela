# 团队认领与开工入口

在已打开本仓库的开发会话中，成员可以直接发送“我是B”“我是C”“我是D”或“我是E”。这表示认领对应角色，并开始当前职责范围内的开发，无需再粘贴长提示词或询问是否开始。

## 角色路由

| 用户提示       | 角色内容                                 | 必须阅读的角色入口         |
| -------------- | ---------------------------------------- | -------------------------- |
| 我是B / 我是 B | IEDU、课程主数据、共享资料及题库         | [B/README.md](B/README.md) |
| 我是C / 我是 C | 学习通、智慧树、平台课程、资料读取及作业 | [C/README.md](C/README.md) |
| 我是D / 我是 D | 校园社区、校园地图和公共实用信息         | [D/README.md](D/README.md) |
| 我是E / 我是 E | 学校邮箱、学在吉大、笔记及摘要接口       | [E/README.md](E/README.md) |

提示中附有具体任务时，先遵循用户最新任务，再用对应角色文档约束职责。仅认领角色时，按以下规则选择首项未完成的工作并开始。角色认领表示当前会话职责，不伪造永久人员登记，也不代表已经创建分支、分配远程任务或锁住代码。

## Agent 收到认领后的动作

1. 阅读根目录 `AGENTS.md`、[项目主页](../../README.md)、[完整计划](../sources/开发完整内容.md)和本角色的全部九份文档。账号方案按用户最新选择，不恢复旧规划要求。
2. 阅读[公共能力接入](../public-integration.md)、[公共身份](../public-identity.md)、[工程说明](../foundation.md)、[数据规则](../local-data.md)和[界面基线](../design/README.md)。
3. 检查当前分支、工作区、模块实际代码、相关提交及测试，确认已有交付。保留其他成员未提交改动；不清理工作区，不把 A 的修改混入本角色成果。
4. 用简短进度说明当前角色、首个可交付流程、复用能力及依赖，然后直接开展代码工作。只在缺少影响正确性的决定时询问，不重复询问已确定的账号方案或“是否开始”。
5. 从角色的开发顺序中选择首项尚未完成且可以推进的完整流程；若已完成则接续下一项，不重建已有功能，也不在一次修改中铺开所有业务。
6. 依赖未交付时提出具体需求，继续解析、模型、本地数据、业务逻辑或隔离测试等独立工作。正常应用不伪造身份、连接、文件或模型成功结果。
7. 实施必要的页面、接口、迁移和行为测试，完成相关检查。按角色 `08-handoff-template.md` 汇报本次结果及可接续任务；模板无需每次复制出一份永久新文件。

## 第一项工作的选择

| 角色 | 优先检查与推进                                                         | 关键交接                                               |
| ---- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| B    | 现有教务流程和课程引用；先公布可供消费者使用的课程语义，再补资料库流程 | 向 C—E 提供课程引用，向 D 提供资料引用                 |
| C    | 复用已有平台，完成课程绑定到作业和原页面访问；有真实条件后再接另一平台 | 消费 B 的课程，平台私人资料明确发布后才进入 B 的共享库 |
| D    | 两账号的文本帖子评论与权限；地图作为独立流程推进                       | 消费 A 的身份和文件、B 的课程与资料引用                |
| E    | 邮件收发及失败保留；与网课笔记分开交付                                 | 消费 B 的课程、A 的来源及凭据和后续备份                |

表格是选择工作的顺序，不是对现有实现的判断。以实际基线识别未完成项；用户明确指定的当前工作优先。

## 共同边界

每人承担自己的客户端、必要服务端、业务数据、契约和测试。A 主责公共壳、认证、学院身份、网络存储入口、公共文件与备份；各成员可提出必要公共修改，与 A 及直接消费者共同对齐。

前端保持原设计，不预建插件框架或空模块，不擅自扩展旧版功能。生成客户端由工具更新，迁移只新增，已发布迁移不改写。

“我是B”等提示授权当前角色内的开发和本地验证，不自动授权远程推送、创建或合并 PR、生产部署或向其他人发送消息。提交和 PR 遵循当前用户授权、贡献指南及本角色约束。

`AGENTS.md` 仍遵循其人类维护规则，本次通过根 README 的必读入口承接角色路由，不修改该文件。
