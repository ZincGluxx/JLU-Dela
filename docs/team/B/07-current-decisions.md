# 当前共同决定

版本：2026-11-13，仓库协作版。用于 B—E 认领和开工，不沿用旧规划分工。本文记录产品要求，实际公共能力以仓库当前代码及接入说明为准。

## 产品与工程

面向吉林大学学生，包含教务、资料库、学习平台、社区地图、邮箱和网课笔记。沿用 Flutter / Dart、Rust、现有 OpenAPI 和部署框架；前端先保持原设计。旧 Electron 位于 `app/`，只作为行为参考，不默认全部迁移。

每人负责本模块客户端、必要服务端、数据、契约和测试。A 负责公共基础，业务负责人不能只交页面、也不能把全部后端交给 A。

## 最新账号方案

- 手机号验证码登录；新手机号首次建立应用账号，已有手机号进入原账号。
- 用户名唯一，6—10 位，仅允许 a-z 和 0-9，表达式 `^[a-z0-9]{6,10}$`。不额外要求两种字符同时存在；重复提醒用户更换。
- 新设置密码 8—16 位，必须同时含小写字母、大写字母和数字；特殊符号可选。前后端规则由 A 统一实现。
- 昵称与用户名分开；账号归属始终使用稳定用户 ID，不使用昵称、手机号或用户名作为业务外键。
- 手机号登录后提交学籍报告在线验证码，由 A 自行实现服务端查询与解析。仅参考 ChsiOnlineVerification 的思路，不引入或复制其实现。
- 本版按报告核验结果进行学生验证，不追加 CAS、校邮、人脸或报告持有人比对等认证因素。B—E 不重新设计这项决定。
- 沿用 `/me` 的 `student_verified` 与可空 `college`；学院只能来自服务端核验结果。具体新增字段和接口以 A 合入的 OpenAPI 为准。
- 学生已验证与学院已确认是两个条件。学院缺失时不能自行猜测，不能将客户端学院选择当作资格。

旧文档里“学信网公开登录接口”“验证后再建立应用账号”等冲突表述，以本次决定为准。仓库内原有认证方式继续由 A 处理兼容；B—E 不擅自删除邀请或密码登录实现。

## A 的交付范围及状态

PR #35 据主开发说明已合并。手机号登录、账号设置、报告核验、公共权限及接入基础由 A 主责；当前代码入口与尚缺的真实短信、报告等条件见[公共能力接入](../../public-integration.md)。B—E 开始前应阅读其最新内容，不把本文件当作代码完成状态清单。

任务书不代表外部验收通过。开始开发时检查自己的分支基线、当前接口和 A 的交接记录；工作区已有 A 的未提交改动时保留，不混入本角色提交。未交付依赖明确登记。

A 主责应用壳、公共主题、认证、公共网络、存储入口、来源连接公共层、公共文件能力、备份同步、契约工具与集成。文件及备份完整实现不作为本次其他成员开工的前提。

## 数据与权限

个人内容本地优先，用户同意后云端备份。共享资料、地图、实用信息、主动发布的社区内容与互动由服务端保存。个人备份不等于发布，平台个人资料不自动进入共享库。

客户端通过现有公共会话读取状态；非 Widget 注入同一控制器，不复制全局用户状态。来源平台连接继续单独使用公共来源体系。服务端从认证上下文取得用户资格，不能相信请求体自报的学生身份、学院或作者 ID。

离线可继续使用已有个人内容，但本地身份缓存不能作为在线资源授权依据。退出、切换用户后隔离业务状态。报告验证码、短信验证码、密码、令牌及 Cookie 不进入普通日志或公开夹具。
