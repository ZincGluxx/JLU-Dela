# B：接口与依赖

以下为需要达成的业务约定，具体字段与端点以合入的 OpenAPI 和公共模型为准，不自行宣布为已有接口。

## B 应尽早提供

| 交接               | 消费者  | 最小语义                                                               |
| ------------------ | ------- | ---------------------------------------------------------------------- |
| 课程引用           | C、D、E | 稳定课程标识、显示名称、学期与必要来源；个人课程与共享引用的作用域明确 |
| 课程查找及绑定候选 | C、E    | 如何取得可选课程、无匹配和课程不再可见时如何处理                       |
| 共享资料引用       | C、D    | 资料 ID、标题、课程、可见范围及受控访问入口                            |
| 文件访问决定       | A、D    | 资料与文件的关联、读取检查位置、发布撤销及删除职责                     |

首个提案使用实际课程样例讨论字段，不自造全校课程大全。A 负责公共 schema 集成，B 负责业务含义。

## B 依赖的 A 能力

当前用户、学生状态、可信学院、公共文件标识及受控上传获取、本地用户作用域和后续备份。客户端身份用于展示，服务端校验资源学院和当前用户资格；不得接受请求中的学院为调用者证明。

未拿到文件能力时先做目录与权限测试，上传入口如实表示不可用，不另建第二套存储。未拿到真实身份时用隔离夹具测试，生产未验证账号不能取得学院资料。

## 可独立推进

教务解析、本地读取展示、课程模型提案、学业完成语义、资料元数据及权限测试。学业完成树保留选择约束和范围，不将子项学分简单累加成毕业结论。

每项记录提供者、所需最小能力、影响流程、可继续工作及提案版本。参考 [08-handoff-template.md](08-handoff-template.md)，不要仅写“等 A 完成”。
