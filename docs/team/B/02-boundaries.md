# B：职责及文件边界

## 主责范围

- Flutter 教务和共享资料功能、所属本地表与解析器。
- Rust 共享资料业务、可见范围及必要教务接口；个人教务读取继续沿用已确认执行位置，不默认全部搬到云端。
- 本模块 OpenAPI、夹具、生成消费与测试。
- 课程引用及共享资料引用的语义，由 B 主责，与 A 和消费者共同对齐。

定位先看 `clients/flutter/lib/features/teaching/`、`features/content/`、`core/storage/course_store.dart` 以及现有教务和资料测试。`content/` 是历史共享位置，不能据目录名认领其中全部通知与来源适配。新增模块位置按实际职责确定，不批量搬目录。

## 与其他成员的界限

| 成员 | 边界                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------- |
| A    | A 提供应用身份、学院结果、公共文件与备份机制；B 实现资料权限、业务关联和本模块数据。B 不改手机号及报告核验流程。 |
| C    | C 负责平台课程、作业和平台个人资料读取；B 负责明确发布后的共享资料。学习通解析由 C 主责，B 不重复实现。          |
| D    | D 通过资料 ID 引用内容；B 提供受限访问规则，二者共同保证帖子引用不扩大资料权限。                                 |
| E    | E 引用课程并独立维护笔记、网课和邮箱；B 不导入其私有页面或 Store。                                               |

## 本角色不扩展的范围

不开发自动选课、毕业资格判定、自动答题、自动提交、题目生成、通用搜索平台或完整知识图谱。不恢复旧通知任务，也不把旧版全部功能迁移作为职责。

需要公共模型、迁移聚合或存储入口改动时，提交明确需求和调用点，由 A 协调。共享学院目录不从用户自填资料产生可信资格。
