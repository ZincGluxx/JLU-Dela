# B：开发内容与交付顺序

你负责 IEDU、课程主数据和共享资料库，包括客户端、必要服务端、业务数据、契约和测试。

## 教务

复用并补齐现有学期、教学周、节次、课表、调停课读取与展示，增加计划内的学业完成查询。保留来源、学期、获取时间和学校计算时间。失败保留旧内容，区分无记录、未连接、无权限与更新失败。

课程按稳定标识和学期组织，同名不能直接合并。向 C、D、E 提供可以引用的课程身份；需区分某用户的来源课程与可共享的课程引用，不能把个人课表直接公开给其他账号。

## 资料与题库

建设按学院、课程组织的目录和详情，支持学生上传、学校公开资料收录及按权限获取文件。保留标题、类型、来源、时间、归属和可见范围；题库作为资料类型管理。

共享目录与文件分开；下载缓存留在本地。学院内部资料的目录、详情及文件都需执行服务端权限判断。个人备份不自动发布，C 的平台材料也不能因被读取就进入共享库。

## 先后顺序

1. 核对已有教务与资料实现，公布课程引用最小提案，优先解除 C—E 的依赖。
2. 跑通一次课表读取、存储、展示及失败保留流程，再补学业完成查询。
3. 完成资料目录、详情及权限；与 A 对齐文件接口后跑通一次上传和获取。
4. 补课程引用联调、题库分类及本模块授权备份接入。

每项均交付真实调用链。未开放的外部来源、文件或同步能力登记依赖，不伪装成功。
