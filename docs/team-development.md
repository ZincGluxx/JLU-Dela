# 五人团队开发分工

本方案依据[开发完整计划](sources/开发完整内容.md)，重新划分五名成员的开发内容、工作范围和协作边界。A—E 是角色代号，可按成员能力对应到具体人员；不沿用旧任务编号和排期，也不表示各模块工作量相同。

每名业务负责人负责本模块的客户端、必要服务端、业务接口、数据变更及测试。A 负责公共基础和集成，不包办其他人的服务端开发。前端保持原设计，沿用现有 Flutter / Rust 工程。

## 分工总览

| 成员 | 主责                                       | 主要交付                                             |
| ---- | ------------------------------------------ | ---------------------------------------------------- |
| A    | 公共基础、身份权限、备份同步、工程集成     | 账号闭环、公共基础能力、授权备份同步、集成与发布流程 |
| B    | IEDU、课程主数据、数据库与资料库           | 课表、学业完成、统一课程标识、共享资料与题库         |
| C    | 学习通、智慧树、平台课程与作业             | 两个平台连接、课程绑定、资料读取、作业与提交入口     |
| D    | 校园社区、校园地图、公共实用信息           | 社区与互动、内容管理、三维地图和地点信息             |
| E    | 学校邮箱、学在吉大、个人笔记与 AI 摘要接口 | 邮件收发、网课观看、笔记与回放关联、自有模型接入边界 |

## A：公共基础与工程集成

### 开发内容

- 实现手机号唯一账号、用户名昵称与密码、登录退出，以及学信网报告学校精确为吉林大学和真实“分院”学院的核验。同一报告可用于多个手机号账号；不处理学生唯一标识、学号、姓名或生日，不限制学籍状态、不自动过期或要求重复核验，也不做本人核对。
- 提供当前用户、学院身份和公共权限判断能力，供资料库及社区使用。
- 维护客户端应用壳、路由、公共主题、网络层、本地存储入口及账号切换隔离。
- 建设个人备份和多端同步的公共机制，提供授权、范围选择、上传恢复、状态与冲突处理；业务数据内容由各模块负责人定义和接入。
- 维护公共文件存储访问能力，供 B 的资料、D 的社区图片及个人备份使用；文件可见范围由所属业务决定。
- 维护契约工具、迁移集成、CI、运行配置和发布恢复流程，组织跨模块联调。

### 工作范围与约束

主要涉及 `clients/flutter/lib/app/`、`core/`、认证与公共设置，服务端公共基础和身份模块，以及 `contracts/`、`infra/` 的公共配置。

- 不将 B—E 的业务接口、页面和数据库表全部收归自己实现。
- 公共代码按实际调用需要扩展，不预建完整插件系统、通用工作流或无调用方的抽象。
- 报告曾核验、应用登录和来源平台连接分别处理；报告核验不证明实时在读、本人或报告持有人。公共入口与真实验证范围见[公共能力接入](public-integration.md)，不将先前 checkout 结果当作最新 PR 基线验收。开发固定码仅限显式开启的 debug loopback，生产拒绝；服务端迁移最终 schema 为 8。
- 备份必须由用户主动开启，不上传普通业务备份之外的平台凭据。
- 负责公共修改的集成评审，各成员仍可在自己的功能 PR 中提出所需公共变更。

### 完成标准

用户可以完成账号流程，各模块取得一致的身份与权限上下文；至少一个真实业务数据类型能完成授权备份和另一客户端恢复，之后按模块逐项接入。运行、迁移和检查流程可复现，并记录实际验证范围。

## B：教务与共享学习资料

### 开发内容

- 接入 IEDU，完成学期、教学周、课表、调停课和学业完成查询的读取与呈现。
- 维护统一课程标识及学期、来源等基本信息，向 C、D、E 提供课程引用能力。
- 建设资料目录、学生上传、学校公开资料收录、资料详情、文件获取与本地缓存。
- 按学院和课程组织资料与题库，保留来源、类型、更新时间及可见范围。
- 使用 A 的身份能力落实学院内部资料权限，提供社区引用资料所需的查询和访问接口。
- 定义本模块个人数据的备份内容，接入 A 的公共机制，保留来源和时间信息。

### 工作范围与约束

负责教务与共享资料相关 Flutter 功能、必要服务端接口和数据结构；现有 `teaching/`、`content/` 中对应代码按实际职责维护，不承接其中所有历史功能。

- 不负责学习通、智慧树和学在吉大的来源解析，也不直接修改它们的课程绑定逻辑。
- C 取得的平台个人资料不自动变成共享资料；进入共享库需明确上传或收录及可见范围。
- 不按课程名直接合并课程，保留学期和来源标识；课程公共模型变更与 A 及消费者共同确认。
- 学业完成结果保留学校的统计含义和计算时间，不自行扩展为毕业审核或自动选课。
- 学院限制在服务端生效；目录、文件及被社区引用时保持同一访问边界。
- 题库按资料管理，不自行增加自动答题或自动提交功能。

### 完成标准

用户可以查看课表和学业完成情况，上传或获取有权访问的课程资料；学院限制覆盖目录及文件访问。C、D、E 能引用同一课程，D 能引用资料而不复制文件或绕过权限。

## C：学习通与智慧树

### 开发内容

- 分别实现两个平台的连接、状态展示和课程获取。
- 将平台课程绑定到 B 提供的课表课程，保存学期及来源课程对应关系。
- 读取平台资料目录，提供有权访问内容的查看、获取及来源页面入口。
- 展示课程作业、截止日期、平台提交状态和最近获取时间。
- 提供原平台作答与提交页面入口，处理访问失败、需要重连及刷新失败提示。
- 将课程绑定和个人平台数据接入本地保存与授权备份流程。

### 工作范围与约束

负责平台连接的具体适配、课程与作业相关 Flutter 功能、本地数据，以及确有业务需要的服务端接口。复用公共来源连接能力，不为两个平台复制整套公共网络和凭据管理代码。

- 不维护共享资料库、题库或社区；需要将平台资料分享给其他用户时，走 B 的明确发布流程。
- 不修改 B 的教务采集和课程主数据，以课程标识建立关联。
- 两个平台独立记录连接及更新状态，不将学习通成功视为智慧树成功。
- 仅跳转到原平台提交，不扩展自动作答、自动提交或代操作。
- 截止时间及状态保持来源含义，相对时间保留获取时间，不伪造精确时刻。
- 更新失败时保留本地成功数据，不把网络故障一律当作应用账号失效。

### 完成标准

两个平台分别完成连接、课程获取、课表绑定、资料访问、作业查看和原页面跳转；断网或来源失效时，用户仍能理解已有数据和当前状态。

## D：校园社区与地图信息

### 开发内容

- 实现全校和学院板块、图文帖子、列表搜索筛选与排序、详情及编辑删除。
- 实现评论、回复、点赞、收藏、个人内容列表和互动通知。
- 实现举报与内容管理入口，保存处理结果并展示状态。
- 对接 B 的课程和资料引用，使用 A 的身份与学院权限能力。
- 建设校园三维地图、校区建筑及教师办公地点、科室位置的查找与详情。
- 维护地图和实用信息的云端数据、更新及客户端缓存。

### 工作范围与约束

负责社区、地图和公共实用信息的客户端页面、服务端接口、数据结构与测试。社区通知由本模块负责，不因此增加跨业务通用通知平台或系统推送承诺。

- 不重复建设资料库或账号系统，社区图片与附件复用公共文件能力。
- 帖子引用的受限资料继续检查原权限，不能通过摘要、附件副本或直接链接扩大可见范围。
- 仅向用户展示昵称等公开信息，不将学号等校验信息附带到帖子。
- 社区发布与个人备份分别管理，未发布草稿不自动上传发布。
- 地图展示教师办公地点，不扩展到教师实时位置跟踪。
- 保持既有界面风格，不借社区或地图功能进行整体视觉改版。

### 完成标准

至少两个学生账号可以实际发布、回复和互动，学院板块与资料引用按权限访问，举报可处理；地图可查找并定位到对应地点，公共信息可由服务端更新。多人社区不能以本机示例数据作为完成依据。

## E：邮箱、网课与个人学习记录

### 开发内容

- 完成学校邮箱连接、邮件列表与正文、收发回复转发、草稿和附件处理。
- 接入学在吉大课程及回放，完成观看入口和相关状态展示。
- 实现个人笔记编辑、保存以及课程、回放、时间位置关联。
- 将个人笔记接入 A 的授权备份同步能力，并处理本模块的编辑冲突呈现。
- 定义并预留自有模型摘要接口，明确输入、输出和生成状态；模型服务可用后完成调用与结果展示。
- 区分个人笔记和 AI 摘要，保留生成失败时可继续使用的基础记录流程。

### 工作范围与约束

负责邮箱、学在吉大、笔记与摘要相关客户端代码、必要服务端接口及数据。课程引用复用 B 的模型，凭据和文件处理复用 A 的公共能力。

- 不负责模型训练、模型选型或新增推理部署平台；本计划中的 AI 工作以接口预留和接入为界。
- 不将网课播放扩展成录像批量下载、公开转存或自动转写项目。
- 邮件收发服务器同步与应用云端备份分开，邮箱凭据不进入普通学习数据备份。
- 不默认把邮件、全部笔记或全部本地资料发送给模型，输入范围必须明确。
- 模型暂不可用时，观看和笔记仍可独立使用；邮件发送失败保留编辑内容。
- 不新增通用聊天、终端、远程工程等旧版工作台功能。

### 完成标准

用户可以收发邮件并处理附件，观看对应网课并记录可返回播放位置的笔记；笔记能接入授权备份。摘要接口边界和状态完整，已接入模型与仅预留接口分别记录。

## 共同约束

1. 每人负责自己模块的完整流程、接口、数据变更、测试和必要文档，不能只交页面截图或孤立 API。
2. 公共壳、主题、认证、网络、本地存储入口、共享模型及迁移集成由 A 主责；业务负责人提出改动并与 A 及直接消费者共同确认，不各建一套。
3. 各模块的数据库迁移由模块负责人编写，A 负责顺序和公共影响协调；已发布迁移不改写，生成代码不手改。
4. 所有人沿用既有设计。模块页面由本人实现，公共组件不足时再协调扩展，不将前端工作统一甩给 A。
5. 个人内容本地优先，用户授权后才进入备份；社区、公共资料和地图按在线业务保存，服务端落实权限。
6. 分支围绕具体功能或修复创建，一个 PR 服务于同一主题。跨模块修改明确涉及的消费者，不整片覆盖他人的改动。
7. 格式化后运行相关本地检查；来源账号、平台设备和真实多用户场景按受影响范围验收。模拟数据不得作为真实接入的完成证明。
8. 不恢复旧计划中的自动任务、不默认迁移旧版全部能力、不预先创建未使用的抽象或模块。`AGENTS.md` 的维护遵循其文件规则。

## 关键交接与启动顺序

| 交接           | 提供者 | 消费者     | 先对齐的内容                                   |
| -------------- | ------ | ---------- | ---------------------------------------------- |
| 身份与学院权限 | A      | B、C、D、E | 当前用户、学院资格、账号与来源状态的区别       |
| 公共文件能力   | A      | B、D、E    | 文件归属、访问边界、上传下载及删除职责         |
| 课程引用       | B      | C、D、E    | 课程标识、学期、来源和失效处理                 |
| 共享资料引用   | B      | C、D       | 资料标识、可见范围、访问及明确发布流程         |
| 备份同步       | A      | B、C、D、E | 各模块参与范围、授权、数据版本、恢复及冲突结果 |
| 摘要接口       | E      | A 参与集成 | 输入输出、凭据位置及生成状态；不含模型训练     |

先完成上述公共边界和最小契约，再分别按业务样例推进页面与逻辑；明确标注的夹具可以用于开发，联调和验收时换为实际实现。公共模块未完成时，各负责人仍可推进模块内部逻辑，不伪造生产成功状态。

每条业务线先交付一个可运行流程，再补齐其余范围：A 完成账号到授权备份，B 完成课表到资料获取，C 先完成一个平台再复用经验接另一个，D 分别完成多人讨论和地点查询，E 分别完成邮件收发及观看记笔记，最后接入摘要。

## 工作量与待定信息

这份分工保证全部需求有负责人，不保证五人的工时天然相等。A 的公共基础会影响所有人，需优先交付最小可用能力；D 同时涉及社区与三维地图，E 同时涉及邮箱和媒体播放，应拆成独立交付项，避免同时铺开。

尚未提供成员技能、每周可投入时间、目标平台及目标日期，因此暂不承诺工期。身份接口、智慧树接入、三维地图资源和自有模型的外部条件由对应负责人登记阻塞及所需支持；单项未具备条件时继续推进本模块独立部分，不擅自换目标或把占位实现标为完成。
