# B—E 公共能力接入

本说明用于角色开工，保留现有 Flutter / Rust 公共边界，不把本地未合入代码或规划写成远端接口。主开发 A 已确认前置工作完成；各成员应确认相关实现是否包含在自己当前分支及运行配置中。

## 身份

Widget 通过现有 `SessionScope.of(context)` 使用同一个 `SessionController`，非 Widget 注入该控制器。当前用户 ID 用于个人数据归属；`studentVerified` 与 `college` 用于展示。来源平台状态继续使用 `SourceContext` / `SourceSessionRegistry`，与应用账号分开。

服务端从 `AuthenticatedUser` 取得当前账号和可信学生结果；具体学生与学院检查调用以当前公共实现为准。业务目录、详情、文件和社区引用都要在所属业务服务端判断权限，不信任请求体自报的学院或作者资格。

## 当前产品选择

手机号验证码建立或登录应用账号；另提交学籍报告在线验证码，由服务端独立实现报告查询和绑定。用户名、密码及范围见[共同决定](team/B/07-current-decisions.md)和[完整计划](sources/开发完整内容.md)。账号设置与报告核验由 A 主责，B—E 不重复实现，也不额外增加 CAS、校邮或本人比对流程。

具体端点、字段及可用状态以 [OpenAPI](../contracts/openapi.yaml)、生成客户端和 A 实际合入提交为准。任务文档不能代替短信提供方、真实报告或目标设备的验收记录。公共接口缺失时向 A 提出具体需要，不在生产使用测试成功替身。

## 页面、来源与存储

沿用 `clients/flutter/lib/app/` 的应用壳与页面注册、`core/` 的网络和存储入口。必要公共修改列出调用点，与 A 及直接消费者对齐，不新建全局认证、数据库或主题。

业务数据使用当前账号作用域；退出和切号后清理本模块私有内存状态。来源读取按现有已确认执行位置推进，来源失效不等于应用账号退出；失败保留上次成功内容。

业务路由接入现有 Rust router，复用状态、错误响应和中间件。业务负责人编写迁移，A 协调聚合；只新增迁移，不改已发布历史。OpenAPI 变更通过工具生成客户端，不手改生成结果。

## 成员协作

| 提供者 | 公共或业务能力                             | 消费者                            |
| ------ | ------------------------------------------ | --------------------------------- |
| A      | 身份、公共壳与网络存储、文件及后续授权备份 | B—E                               |
| B      | 课程引用及学期、共享资料与访问规则         | C、D、E                           |
| C      | 平台课程及映射、平台私人资料和作业         | 对应学习流程；共享需走 B 明确发布 |
| D      | 社区发布互动、地图与公共信息               | 对应用户流程                      |
| E      | 邮箱、回放、笔记及摘要输入边界             | 对应学习流程                      |

个人数据本地优先，授权备份不自动公开；社区发布、共享资料和地图在线保存与个人备份分开。文件及备份的具体契约由 A 与业务方确认，不因文档列出职责就添加占位成功接口。

## 验证
