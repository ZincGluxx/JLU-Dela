# 开发完整计划

## 规划定位

本计划面向吉林大学学生，围绕课程学习、校园信息、学习资料管理和校园社区建设统一客户端。项目沿用原有工程框架，前端先保持原设计；后续功能开发以本计划为依据，原有开发计划不再作为功能范围和实施顺序的依据。

服务端负责账号与身份、公共内容保存，以及用户授权后的备份和多端同步；客户端负责平台连接、数据呈现与日常学习操作。除必要的云端数据外，个人数据优先保存在本地，由用户决定是否上传备份。

本文描述计划建设的能力，不用于记录现有功能完成状态。

## 服务端

### 用户的登录校验

通过手机号验证码建立或登录应用账号，再由服务端查询学信网报告，校验吉林大学学生身份及学院归属。应用登录与学生验证分开；普通账号资料修改不能自报学生或学院资格。

- 每个应用账号分配独立且稳定的用户 ID，用于关联个人数据、课程绑定、笔记和云端备份。
- 登录后可设置用户名、昵称和密码。新用户名为 6—10 位 ASCII 小写字母或数字，不做大小写或空白归一化；新密码为 8—16 个 Unicode 标量值，包含 ASCII 大写字母、小写字母和数字。旧账号密码登录规则保持兼容，不套用新设置规则。
- 同一学生身份最多绑定一个账号；重复报告校验不能将其绑定到另一账号，也不自动合并账号或迁移个人数据。
- 学院归属作为学院内部学习资料的访问依据，与账号身份一并管理。
- 应用账号与学习通、智慧树、学校邮箱等平台的连接分别管理，用户按需要连接对应平台。

本模块形成统一的用户身份，为个人数据归属和学院资料权限提供依据。

### 客户端数据云端备份

提供可选择的云端备份与多端同步能力，覆盖 IEDU、学习通、智慧树的数据，以及题库、资料库和学在吉大的网课笔记等内容。

- 个人数据默认保存在本地。用户同意后，按其选择的范围上传云端备份，并在同一账号的其他客户端恢复或同步。
- 平台数据保留所属平台、学期及获取时间，方便判断来源和更新情况。
- 课程绑定关系随个人数据保存，使用户在其他设备上继续使用已整理的课程对应关系。
- 网课笔记保留课程、回放及相关时间位置，避免同步后失去学习上下文。
- 题库和资料库区分个人内容与共享内容，分别按照个人备份范围和共享访问权限处理。
- 客户端展示最近成功时间、待同步内容和失败提示；断网时保留本地内容，恢复连接后继续同步。

备份用于恢复已保存的数据，同步用于延续多端使用过程。多端编辑发生冲突时，应保留用户内容并提示处理，避免直接覆盖笔记等个人记录。

### 部分服务的云端保存以同步至客户端

将校园地图和实用信息统一保存在服务端，向客户端提供一致的数据来源。

- 校园地图按校区、建筑和具体地点组织，并关联教师办公地点、科室位置等说明。
- 实用信息围绕校园生活和办事需要整理，包含办事地点、服务时间、联系方式及相关页面入口。
- 公共内容保留来源和更新时间，便于维护、更正和客户端更新。
- 客户端获取更新后保留本地缓存，公共数据更新与个人数据备份分别处理。

本模块负责公共内容的统一维护与分发，避免各客户端重复维护同一份校园信息。

### 社区内容与互动服务

为校园社区提供帖子、评论和互动数据的统一保存与分发，复用应用账号和学生身份体系。

- 保存帖子正文、图片、所属板块、作者及发布时间，支持作者编辑和删除自己的内容。
- 管理评论、回复、点赞与收藏，并向用户提供自己发布、参与和收藏的内容列表。
- 根据板块的可见范围提供内容。全校交流内容面向已验证的学生，学院内部内容按学院身份控制访问。
- 支持帖子关联课程和资料库条目；关联内容继续遵守原有权限，不能通过帖子绕过学院资料限制。
- 提供内容举报和管理入口，支持管理员处理举报、下架违规内容，并向相关用户展示处理状态。
- 保存回复与评论通知，客户端展示未读状态，方便用户继续参与讨论。

社区发布和互动属于在线共享服务，其数据由服务端保存，与用户自行选择的个人云端备份分别管理。

## 客户端

### 邮件收发

建立学校邮箱收发客户端，替代日常使用中的网页邮箱入口，让用户在应用内完成邮件处理。

- 连接学校邮箱，查看邮件列表、正文及附件。
- 支持撰写、发送、回复和转发邮件，并提供附件选择与下载入口。
- 支持保存草稿，区分发送中、发送成功和发送失败；失败时保留已编辑内容，方便再次发送。
- 展示邮箱连接状态和邮件同步状态，便于区分账号连接问题与网络问题。
- 邮件内容优先在本地保存。邮箱自身与邮件服务器的收发同步，与应用提供的云端备份分别管理。

### IEDU 数据呈现

解析并呈现 IEDU 中与学生日常学习直接相关的数据，重点建设课表和学业完成查询，相关数据范围参考 [[jlu-data-feasibility]]。

- 课表按学期、教学周和节次呈现，展示课程名称、教师、上课时间与地点，并体现调停课信息。
- 学业完成查询展示学校提供的学分要求、已完成情况及分类明细，帮助学生了解学业进度。
- 数据保留来源、所属学期和更新时间；学业完成情况同时保留学校提供的计算时间，便于理解统计结果。
- 以课表课程作为关联入口，连接学习通、智慧树中的课程、资料和作业。
- 更新失败时保留已有内容并提示状态，避免将获取失败显示为空课表或无学业记录。

本模块以查询和呈现为核心，将分散的教务学习信息集中到客户端。

### 校园地图

展示来源于吉大官网的校园三维地图，并补充教师和科室的位置，帮助学生查找校内地点。

- 按校区组织地图，从校区进入建筑及具体地点。
- 地点信息关联建筑名称、楼层、房间和相关说明，方便从地图位置找到实际办事地点。
- 教师位置以办公地点为主，科室位置与办事信息对应展示。
- 支持按地点、教师或科室名称查找，查看对应位置与详情。
- 地图和地点信息从服务端获取更新，客户端保留已获取内容供后续查看。

三维地图承担空间展示，地点信息承担查找与说明，两者通过地点关联。

### 学习通、智慧树

绑定用户的学习通和智慧树，将平台课程与课表课程关联，集中管理资料、作业和截止日期。

- 两个平台分别连接，分别展示连接状态和课程列表。
- 用户为课表课程选择对应的平台课程；关联时保留学期和来源课程信息，避免同名课程混淆。
- 在课程入口展示已关联平台的资料目录，支持查看、获取资料及返回原始页面。
- 汇总课程作业，展示作业名称、所属课程、截止日期和平台提供的提交状态。
- 提供跳转到提交页面的入口，由用户在来源平台完成作答和提交。
- 作业与资料保留最近获取时间，刷新失败时继续展示原有内容，并提示当前状态。

本模块围绕课表课程、平台课程、资料与作业建立对应关系，减少跨平台查找同一门课的操作。

### 数据库与资料库

客户端建立初始为空的资料数据库，从服务端获取可访问的资料目录和内容。资料来源包括学生上传的内容和学校公开的学习资料，部分学院内部资料需验证学院身份后才能访问。

- 按学院和课程组织资料，展示标题、类型、来源及更新时间。
- 资料目录与具体文件分别管理，用户先浏览目录，再按需获取文件。
- 学生上传的资料保留上传来源、课程归属和可见范围；学校公开资料保留原始来源。
- 公共资料按公开范围提供访问，学院内部资料由服务端根据学院身份判断访问权限，客户端展示对应提示。
- 题库保留课程归属及内容来源，与资料库共同管理。
- 下载后的资料保存在本地；私人资料是否进入云端备份，由用户选择。

数据库用于组织和检索资料，资料库用于管理具体学习内容，两者共同支撑课程资料的浏览与获取。

### 学在吉大

获取学在吉大的网课内容，在客户端提供课程学习与笔记入口，并预留 AI 摘要接口，后续接入自有模型。

- 按学期和课程组织网课及回放，用户从课程进入对应内容。
- 在观看入口附近提供笔记功能，记录课程重点、问题及个人理解。
- 笔记与课程、具体回放关联；涉及片段的笔记保留时间位置，方便返回对应内容。
- 笔记默认保存到本地，用户开启云端备份后，可在其他客户端继续阅读和编辑。
- AI 摘要围绕对应课程内容生成，与用户笔记分开展示，供用户参考和整理。
- 预留自有模型调用入口，明确摘要输入、生成结果与生成状态；模型接入独立于基础笔记功能，使网课与笔记可以先行使用。

本模块将观看、记录和摘要组织在同一课程上下文中，帮助用户回顾学习内容。

### 校园社区

建设面向吉林大学学生的校园交流社区，围绕学习讨论、课程经验、资料分享和校园生活提供发帖与互动入口。

- 按主题组织板块，提供全校交流和学院内部交流空间；学院板块与已有身份体系关联。
- 支持发布文字和图片帖子，设置标题、板块及相关课程，发布前明确展示内容的可见范围。
- 支持浏览帖子、按板块或课程筛选，以及搜索标题和正文；提供按发布时间和热度排序的方式。
- 支持评论、回复、点赞和收藏，在个人入口集中查看自己发布、参与及收藏的内容。
- 学习讨论可以关联课程，资料分享可以引用资料库条目，减少同一份资料重复上传；受限资料仍按原有权限访问。
- 提供回复与评论通知，从通知返回对应帖子和讨论位置。
- 帖子使用应用昵称展示，学生身份用于访问和权限判断，不直接展示学号等身份校验信息。
- 支持举报帖子与评论，并提供作者编辑、删除及查看处理状态的入口。
- 未发布的帖子草稿优先保存在本地；用户主动发布后，内容及附件上传服务端并按选定范围展示。发布失败时保留草稿，便于重试。

本模块连接学生之间的交流与已有课程、资料入口，形成从提出问题、参与讨论到查阅资料的使用流程。

### 前端显示

前端先按原设计保持不变，沿用原有页面结构、视觉样式和操作习惯，在现有框架中接入本计划中的功能。

- 新增模块优先使用现有导航、内容区和通用组件，保持交互一致。
- 在对应功能内展示登录、平台连接、加载、同步及权限状态。
- 课程相关内容通过关联入口互相跳转，减少重复配置。
- 本阶段以功能接入和使用流程完整为目标，不单独展开整体视觉改版。

## 数据处理

除必要云端保存的资料库、数据库、校园地图，以及用户主动发布的社区内容和互动数据外，其余内容优先保存在本地，经用户同意后上传云端备份。

### 数据保存范围

| 数据类别                             | 保存方式                                 | 主要用途                         |
| ------------------------------------ | ---------------------------------------- | -------------------------------- |
| 账号与身份信息                       | 服务端保存账号识别和权限判断所需信息     | 登录、个人数据归属和学院权限判断 |
| 公共资料目录、共享题库及资料文件     | 云端统一保存，客户端按权限获取           | 资料共享与课程学习               |
| 校园地图与公共实用信息               | 云端统一维护，客户端保留缓存             | 公共信息分发与地点查找           |
| 已发布社区帖子、附件、评论及互动记录 | 服务端统一保存，按内容可见范围提供访问   | 校园交流、互动与通知             |
| 未发布的社区草稿                     | 本地优先，用户同意后云端备份             | 内容编辑与发布前保存             |
| IEDU、学习通、智慧树的个人数据       | 本地优先，用户同意后云端备份             | 日常查看与多端延续               |
| 网课笔记、课程绑定及个人资料         | 本地优先，用户同意后云端备份             | 个人整理、恢复和同步             |
| 邮件内容及附件缓存                   | 本地优先，按邮箱收发流程与邮件服务器交互 | 邮件阅读和处理                   |

### 用户授权与数据归属

- 云端备份由用户主动开启，并说明上传内容和用途，不能将登录应用视为同意上传所有个人数据。
- 公共资料上传与个人备份分别处理。备份个人资料不等于向其他用户公开，发布共享资料时需明确可见范围。
- 社区发布与个人备份分别处理。关闭云端备份不影响主动发帖和评论；未发布草稿、私人笔记与平台个人数据不会自动公开到社区。
- 应用账号密码、第三方平台凭据和业务内容分别管理，不将平台凭据作为普通学习数据上传备份。
- 切换应用账号时区分各用户的个人内容，公共缓存与个人数据分别管理。
- 用户关闭云端备份后停止后续上传，并提供对已有云端备份的管理入口。
- AI 摘要按明确的输入范围向自有模型发送内容，不将全部本地资料默认纳入模型处理。

整个使用流程以应用账号确定数据归属，以课程连接课表、平台作业、学习资料和网课笔记，以本地保存支撑日常使用，再由用户选择是否开启云端备份和多端同步。

| 模块               | 预期成果                                                           |
| ------------------ | ------------------------------------------------------------------ |
| 身份与账号         | 建立一名学生对应一个账号的身份体系，支持学院资料权限判断           |
| 云端备份与公共服务 | 支持授权后的个人备份、多端同步及公共内容统一分发                   |
| 邮箱               | 在客户端完成学校邮箱的日常收发与阅读                               |
| IEDU               | 集中呈现课表和学业完成情况，并关联课程学习入口                     |
| 校园地图           | 通过三维地图查找教师办公地点与科室位置                             |
| 学习通、智慧树     | 将平台课程、资料和作业关联到课表课程                               |
| 数据库与资料库     | 提供来自学生和学校的学习资料，按学院身份控制内部资料访问           |
| 学在吉大           | 串联网课观看、个人笔记和自有模型摘要                               |
| 校园社区           | 支持学生发帖、评论和互动，关联课程与资料，并按身份控制内容可见范围 |
| 前端与数据处理     | 延续原设计，保持本地优先和用户授权后的云端备份原则                 |
